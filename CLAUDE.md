# CLAUDE.md

Guidance for Claude Code in this repo: the ZMK configuration of the user's Cyboard Imprint, a wireless split keyboard with a trackball on each half (Cyboard "Assimilator" nRF52840 boards). GitHub Actions builds the firmware (`build.yaml`: board `assimilator-bt` with shields `imprint_left` and `imprint_right`); the `.uf2` files come from the run's `firmware` artifact. The keymap is `config/imprint.keymap`.

The keyboard goes with the user to every machine, so this file holds what belongs to the keyboard. How it interacts with the user's NixOS setup (layouts, Hyprland binds) is documented in the `nixos-config` repo's `CLAUDE.md`.

## Flashing

- Each half in UF2 bootloader mode shows up as a ~32 MB `vfat` USB drive labeled `ASSIMILATOR` with an `INFO_UF2.TXT` (`Board-ID: nRF52840-assimilator-ble`). Copying the half's `.uf2` onto it flashes it; the board reboots and the drive disappears right after. On the user's NixOS machines, `udisksctl mount -b /dev/sdX` mounts it without sudo.
- Both halves report the same `Board-ID`, so `INFO_UF2.TXT` can't tell them apart; the USB serial number can (the chip's ID, the same in the bootloader and in ZMK). With both halves on USB, the left half (the central) enumerates as product `Imprint` and the right half (the peripheral) without a product name (both `1d50:615e`), so read both serials from `/sys/bus/usb/devices/*/serial` before starting. When a bootloader drive appears, walk up from `/sys/class/block/sdX/device` to the USB device directory (the one with `idVendor`) and compare its `serial` before copying.
- Flash one half at a time: tell the user which half to put in the bootloader, wait for its drive, check the serial, copy, and only then ask for the other half. On 2026-10-07 a script that took the first drive to appear as the right half and the second as the left one copied the left firmware onto the right half, because the user had put the right half in the bootloader both times: the right half became a second central and the keyboard stopped working.
- Entering the bootloader from the keyboard: hold layer 2 (`&mo 2`, bottom-right corner key) and press the `&bootloader` key on the half to flash (left half: Esc position; right half: `'` position). `&bootloader` and `&sys_reset` only act on the half they are pressed on, so both halves have them since commit `ae3a7da`.
- Entering the bootloader without the keymap (e.g. after flashing the wrong firmware): double-tap the reset button in the hole next to the half's USB-C port; the switch puller that came with the keyboard fits it (Cyboard's docs).
- A copy can fail without an error: the host reset the USB device in the middle of it (`reset full-speed USB device` in the kernel log), the drive stayed mounted and the half stayed in the bootloader; copying the file again finished the flash (I/O errors at the end of that copy are normal, since the bootloader reboots as soon as it has every block).

## Keymap facts

- The user types with the US International layout (with dead keys), where Right Alt (`RALT`) is AltGr: it types characters instead of acting as Alt in shortcuts. Modifier layers use `LALT` when they mean Alt; the base layer's right thumb keeps `RALT` for accents (the full AltGr list is in `nixos-config`).
- Layer 1 (`&mo 1`, bottom-left corner key, held with the left pinky) holds the nav cluster on the right half (Home, End, PrtSc, Ins, PgUp, PgDn), Shift/Ctrl/Alt on the left home row (S/D/F), Super (`LGUI`) on the left B position, media keys on F7-F12, and `Alt+Shift+<key>` macros (`LA(LS(...))`) on the right number row and home rows. The macros drive the user's own extension, Media Tab Controller (`github.com/MatiasAlmeida/media-control-extension`, Chromium and Firefox/Zen from one codebase), which controls media elements inside pages (including iframes with embedded players), more specific than the standard media keys: `Alt+Shift+` 0 play/pause, 6/8 seek back/forward 5 s, 7 focus the media tab, comma/period speed down/up, 4 quality max, 5 quality cycle. Their order under the media keys (focus tab, seek back, seek forward, play/pause, speed up, speed down) is intentional (confirmed 2026-10-07). On the user's NixOS setup Hyprland binds exactly these combos and forwards them to Zen, so they work from any app; don't use other `Alt+Shift` combinations for something else. Since 2026-10-07 (keymap commit after `ae3a7da`): the four base-layer arrow positions (←/→ on the left half and ↓/↑ on the right half, bottom row) are transparent in layer 1, so they stay arrows there: left Super (layer 1 + B) + ↓/↑ gives Super+Down/Up (Hyprland focus), layer 1 + S/D/F + an arrow gives Shift/Ctrl/Alt + arrow (text selection); the rest of layer 1's left half stays `&none` on purpose (no stray keys while the left hand holds the layer and the modifiers). Layer 1's left Super covers Super+Return/Space/M/PrtSc; Super+Q/D/V/L/1-3 use the right thumb's Super instead, since layer 1 overrides those keys (decision 2026-10-07). Flashed on both halves and confirmed by the user on 2026-10-07. The right thumb's outer key in layer 1 is `LALT` (it was `RALT`, which is AltGr under US intl and types characters instead of acting as Alt); the base layer keeps `RALT` there for accents. Key scrolling (the user's "fine scroll", slower than the trackballs): vertical on layer 1 at the comma (`SCRL_UP`) and period (`SCRL_DOWN`) positions, right under PgUp/PgDn, so the middle and ring fingers only drop one row from K/L while the left pinky holds the layer; horizontal on layer 2 (held with the right pinky) at the mirror positions X (`SCRL_LEFT`) and C (`SCRL_RIGHT`). Both used to be on the bottom row (vertical under ↓/↑ in layer 1, horizontal under ←/→ in layer 2), which needed the ring and middle fingers to reach down next to the pinky holding the layer: unusable per the user. Speed: `ZMK_POINTING_DEFAULT_SCRL_VAL` 60 reached after `time-to-max-speed-ms` 500 with linear acceleration (`&msc`), so a short press is as fine as the old constant 20/150 ms and a long one gets ~3x faster (ZMK's docs don't state the unit; tune by testing).
- Layers 3-6 are activated by the thumb Shift/Ctrl keys (macros `shift_layer`, `ctrl_layer`, etc.) for one-handed multi-modifier chords (two or three modifiers plus a key with one hand, the other free, e.g. on its trackball). With a thumb held, the index finger adds the other half of Ctrl+Shift (left F, right J) and the middle finger adds Alt (left D, right K), mirrored on both halves; only layer 1 differs (D=Ctrl, F=Alt), and it is used in a different situation (navigation, no thumb held). Side effect: same-side shortcuts on those keys don't work (e.g. left Ctrl+F, left Ctrl+D, right Ctrl+K); the user uses the opposite half's modifier and is used to it. Kept deliberately (decision 2026-10-07).
- The trackball combos (H+J+comma: right trackball scrolls; C+F+G: left trackball moves the cursor) have `require-prior-idle-ms = <150>` since 2026-10-07, so they can't fire while typing.
